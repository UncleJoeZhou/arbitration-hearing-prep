# 法律检索来源（由用户自备）

本技能**不捆绑**任何付费法律数据库。法条与案例核验依赖用户在 Agent 里已接好的检索能力。律师常见做法是：**一个 Agent + 若干法律 MCP**（如元典、北大法宝等），本技能只规定「必须经权威来源核验」，不规定你用哪一家。

## 一、安装本技能后请先配置来源

按你实际订阅与账号，在 Cursor / Claude Code 等客户端接入至少一类权威来源：

| 类型 | 常见接入方式 | 用途 |
| --- | --- | --- |
| 法规 / 法条 MCP | 元典法规、北大法宝法规、律所自建法规 MCP 等 | 检索、核对条文全文与时效 |
| 案例 MCP | 元典案例、北大法宝案例、指导案例库 MCP 等 | 检索真实案号与裁判要旨 |
| 网页 / 客户端 | 法宝网页、裁判文书网、仲裁机构公开文书等 | MCP 不可用时的人工核验兜底 |

配置要点：

1. **在 MCP / 工具面板完成登录与授权**（多数商业库要 token 或账号）。
2. **同一 Agent 会话里能同时看到**法规工具与案例工具（可只接一家，也可元典 + 法宝并用）。
3. 装好后新开对话，让 Agent 列一下当前可用的法律相关工具；列不出来就说明还没接上，先别跑正式核验。
4. 本技能不负责替你申请账号、不内置 API Key；密钥只放在你自己的 MCP 配置里，不要写进案件材料或本仓库。

未配置任何权威来源时：仍可做材料梳理与问题清单骨架，但**凡法条、案例必须标注「需核实」**，禁止当成已核验结论写入正式文书。

## 二、Agent 选用来源的优先级

执行「检索核验」步骤时，按下列顺序：

1. **用户本机 / 本会话已启用的法律 MCP**（法规检索、案例检索、法条详情、案例详情等工具），优先用其返回的现行有效文本与可核验案号。
2. 用户在对话里**点名**的来源（「用元典查」「用法宝核对」）——服从用户指定。
3. 用户提供的**已核对摘录 / 截图 / 导出文本**。
4. 公开网页检索仅作线索；写入正式文书前仍须用 1–3 之一核验，否则标「需核实」。

多家 MCP 并存时：

- 不绑定单一品牌；哪个能查出现行有效条文/真实案例就用哪个。
- 结果冲突时，注明分歧，并以可打开的原文（详情页 / 分享链 / 用户导出件）为准，不要自行调和编造。
- 需要可转交的原文链接时，调用该 MCP 的「详情 / 分享」类工具，不要拼未经凭证的 URL。

## 三、核验最低标准（写入文书前）

**法条**

- 完整法规名称 + 条文序号；
- 确认时效（现行有效 / 已修订等）；
- 配「规范效果 · 对应本案争点」。

**案例**

- 案号、法院或仲裁机构、日期、案由齐全；
- 配「适用于本案的结论与建议」；
- 未经 MCP 或权威库核验的检索结果，不得当参考案例用。

## 四、对用户说清楚的一句话

> 本技能管「庭审准备怎么做」；法条和案例从哪查，由你在 Agent 里接好的元典 / 法宝等 MCP（或同等权威来源）决定。
